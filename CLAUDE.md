# CLAUDE.md — La Z'aumunauté dez Z'Agneaux

Jeu HTML5 canvas en pixel art, 100 % statique (aucun build, aucun framework). Propriétaire : Corentin (« Coco »), francophone, tutoiement, ton décontracté. Le joueur est sur téléphone (GitHub Pages) et ordinateur.
Le plan complet « où modifier quoi » est dans **README.md** (tableaux générés à partir des en-têtes de fichiers) : le consulter avant de chercher, et le garder à jour si on ajoute/déplace un fichier.

## Règles à toujours respecter
- **« Elaïs » s'écrit sans É** (jamais « Élaïs ») dans tout texte, code ou doc.
- **Scripts classiques, pas de modules ES.** Chaque `js/**/*.js` est un `<script src>` ; ils partagent la portée globale (les `const`/`let` du haut de fichier sont visibles depuis les autres fichiers). Marche aussi en `file://`.
- **L'ordre des `<script>` dans `index.html` compte.** Les fonctions sont « remontées » mais les `const`/`let`/`class` ne le sont pas : un appel exécuté au chargement ne doit référencer que des fichiers déjà chargés. `js/moteur/demarrage.js` se charge **en dernier** ; `js/minijeux/etoiles.js` et `outils.js` **avant** les fichiers de jeux ; `css/tactile.css` en dernier (il surcharge).
- **Nouveau fichier JS/CSS** = l'ajouter dans `index.html` (avec `?v=`), à la bonne place, avec un en-tête `/* ==== chemin — description ==== */` sur la 2e ligne (le README en est tiré), et mettre à jour le tableau du README.
- **Version** : à chaque livraison, `python3 outils/changer-version.py 20.NN` (met à jour les `?v=` anti-cache, le texte de l'écran-titre et `GAME_VERSION`). Ne pas les éditer à la main.
- **Pas de style inline dans `index.html`**, tout est dans `css/`. Exception volontaire : `#dialoguePortraitWrap` et `#dialoguePortrait` gardent `style="display:none;"` car le JS les révèle en vidant `style.display`. Les éléments cachés par défaut dans le CSS (`#titleScreen`, `#endScreen`, `#assetsWarning`, `#mgCanvas`, `#mgDOM`, `#btnTitleNew`, `#cutsceneImg`…) sont affichés par le JS avec une valeur **explicite** (`'flex'`, `'block'`, `'inline-block'`) — jamais `style.display = ''`.
- **Taille d'écran : JAMAIS de `vh` / `100vh` / `dvh` dans le CSS.** Sur téléphone, `100vh` = hauteur SANS la barre d'adresse → le bas du jeu était coupé (bug v20.27). `js/moteur/ecran.js` mesure `window.innerWidth/innerHeight` et pose `--app-w`, `--app-h`, `--vh` (1 % de la hauteur visible) : on écrit `calc(58 * var(--vh, 1vh))`. Pareil côté JS : `innerHeight`, pas `screen.height`. `ecran.js` est le **premier** script chargé.
- **Téléphone** : classe `body.touch` (pointeur « coarse » ou 1er `touchstart`). Le 1er toucher passe en plein écran + paysage (`enterFullscreen`, une seule fois) ; bouton ⛶ pour y retourner ; iPhone : pas d'API plein écran → astuce « Sur l'écran d'accueil » (`manifest.webmanifest`, `sw.js` vide, meta Apple). La vue du hub épouse le format de l'écran (`fitView()` dans `monde.js`, de 4:3 à 2,4:1 ; `VIEW_W` est donc une variable, `SEE_W` aussi).
- **Petits écrans** (≤ 460 px de haut, et ≤ 330 px avec barre d'adresse) : `css/petit-ecran.css`. Règle d'or : rien ne dépasse de l'écran ou ça défile, et les boutons « Fermer / Continuer / J'ai compris » restent atteignables. Dialogue : « Passer ⏭ » (aussi Échap) saute toute la discussion (`skipDialogue`), toucher n'importe où = réplique suivante. Textes d'aide : `<span class="hintKb">` (clavier) / `<span class="hintTouch">` (toucher).
- **Mini-jeux à canevas sur téléphone** : `mgFitCanvas()` (`noyau.js`, rappelée au lancement, au `resize` et par un `ResizeObserver`) fixe la taille du canevas en px (plus grand rectangle de même ratio que `canvas.width/height`). Si l'écran fait ≤ 460 px de haut elle pose `.mg-compact` sur `#miniGameContainer` (plus de cadre ni de padding : le jeu touche les bords) et, si les marges latérales font ≥ `MG_MARGE_MIN` (104 px), `.mg-wide` (titre + « Quitter » posés dans les marges, par-dessus). `.mgIsCanvas` distingue les jeux canevas des jeux DOM (qui remplissent déjà `#mgBody`). Ne pas remettre de `max-width/max-height` CSS sur `#mgCanvas`.
- Les sons sont synthétisés dans `js/moteur/son.js` (WebAudio, `Snd.play('nom')`) : aucun fichier audio (les 404 `assets/sons/*` en console sont normaux).
- Ne pas toucher à `tableau-des-100-suspects.xlsx` sans l'accord de Coco (fichier public dans le dépôt, il le modifie lui-même).

## Architecture en bref
- Caméra du hub zoomée : `HUB_ZOOM` (2.4) dans `js/moteur/monde.js`. Le canevas fait 480 de haut (640 de large sur ordinateur ; plus large sur téléphone, voir `fitView()`) mais la caméra n'en voit que `SEE_W × SEE_H` (640/2.4 × 480/2.4) du monde : utiliser `SEE_W/SEE_H` (pas `VIEW_W/VIEW_H`) pour tout ce qui touche à la vue du monde. Rochers solides (`rockHit`), arbres traversables.
- Machine d'état `gameState` : `'loading' | 'title' | 'playing' | 'dialogue' | 'miniGame' | 'teamMenu' | 'bigMap' | 'caseJournal' | 'zoneOverlay' | 'endScreen'`.
- Mini-jeux : objets `MINIGAMES[type]` (un fichier par jeu dans `js/minijeux/`), terminés par `mgSuccess()` / `mgFail()` (dans `noyau.js`). Les étoiles (★ de performance + ⭐ bonus) sont décidées par `STAR_RULES` dans `etoiles.js`.
- Course de Coco (`js/minijeux/coco-course.js`, v20.27) : vraie course contre 5 concurrents (IA dans `courseAI`, pas fixe de 1/120 s, `courseStep` testable sans navigateur : `s = {}; courseInit(s, zone); courseStep(s, COURSE.STEP)`). Étoiles = place (1er ★★★, 2ᵉ ★★, 3ᵉ ★) ; 4ᵉ ou plus, ou 3 coureurs déjà arrivés = défaite. Difficulté : `COURSE_RIVALS[].skill` (vitesse), `aggr` (coupe la route), `stumble` (chutes de rivaux). Joueur parfait ≈ 32,6 s, meilleur rival ≈ 33,5–34,7 s, une chute coûte ≈ 3 s. Sur téléphone, pédalage automatique (le joystick ne donne qu'une direction à la fois).
- Commandes tactiles : `#touchUI` est remonté à `z-index: 60` pendant les mini-jeux (`body.t-arrows/t-jump/t-asdf`) car l'écran de mini-jeu est à 35 ; sans ça le joystick était caché.
- Sauvegarde : `localStorage['zaumunaute_save_v2']`, charge utile `v: 3` (`js/moteur/sauvegarde.js`). Ne jamais casser la lecture d'anciennes sauvegardes (migrations).
- Persos : `js/donnees/personnages.js` ; zones/maisons/quêtes : `js/donnees/zones.js` ; enquête (témoignages, indices, suspects `CASE_*`) : `js/enquete/donnees.js`.
- Écran-titre : fond en dégradé nuit → herbe (`css/titre.css`, plus de hub animé derrière) et note grise sur les limites de la sauvegarde (`#saveNote`, bas de l'écran-titre) : `index.html` + `css/titre.css`. Si la sauvegarde change (export de code, cloud…), mettre la note à jour.

## Tester (Playwright + Chromium sont préinstallés dans l'environnement cloud)
- **Tailles de téléphone à tester (paysage, en px CSS visibles)** : 780×273 (Galaxy S23 avec barre d'adresse Chrome), 780×360 (même, plein écran), 844×390, 667×375 (iPhone 8), 568×320 (iPhone SE), 915×412, + tablette 1024×768. Contexte Playwright : `isMobile: true, hasTouch: true`. Vérifier pour chaque écran : tous les boutons visibles ET touchables (`document.elementFromPoint` au centre du bouton = le bouton), rien qui dépasse de la fenêtre, texte de tuto qui ne recouvre pas « J'ai compris ». En mode test headless, après le 1er toucher la page est en plein écran : `setViewportSize` échoue alors (poser `ecranAutoFsFait = true` avant).
```
python3 -m http.server 8125          # dans la racine du dépôt
node --check js/**/*.js              # syntaxe (ou boucle sur chaque fichier)
```
- Vérifier au minimum : démarrage sans `pageerror`, aucun 404 inattendu (hors sons/`.png`/`.jpeg` de repli), l'écran-titre (avec et sans sauvegarde), un mini-jeu, la reprise de sauvegarde.
- Sur mobile émulé, **utiliser un viewport paysage (ex. 844×390)** : en portrait `#rotateHint` intercepte les clics.
- Pour un mini-jeu : `launchMiniGame(zones.find(z => z.id === 'camille'))` depuis `page.evaluate`, puis forcer la fin avec `mgSuccess()`/`mgFail()` ou jouer avec un bot.
